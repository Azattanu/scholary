## 4. Пайплайн персонального отчёта — КОД УЖЕ НАПИСАН, осталось задеплоить

Весь бэкенд лежит в репозитории:

```
supabase/migrations/002_v21_payments_reports.sql  — таблицы reports/programs, RPC get_report, новые поля
supabase/functions/tiptop-webhook/index.ts        — приём оплаты, HMAC-проверка, запуск генерации
supabase/functions/generate-report/index.ts       — движок → тексты Claude → сохранение → WhatsApp + email
supabase/functions/_shared/report-engine.mjs      — автокопия движка (не править; scripts/sync-engine.mjs)
r.html                                            — персональная страница отчёта по секретной ссылке /r.html?t=…
```

Деплой (через Dashboard → Edge Functions → создать и вставить код, или CLI):
```bash
supabase functions deploy tiptop-webhook generate-report --project-ref <PROJECT_REF>
supabase secrets set SB_URL=… SB_SERVICE_KEY=… ANTHROPIC_API_KEY=… \
  RESEND_API_KEY=… EMAIL_FROM="Scholary <report@scholary.kz>" \
  GREEN_ID=… GREEN_TOKEN=… TIPTOP_API_SECRET=… SITE_URL=https://scholary.kz
```

Как это работает после оплаты: вебхук помечает лид → generate-report считает отчёт Тем же движком, что превью на сайте, просит Claude написать тексты (числа модель не выдумывает — только из движка), сохраняет в `reports` и шлёт **секретную ссылку** на WhatsApp и почту. Отчёт открывается на `/r.html?t=<токен>` — страница персональная, из неё же печатается PDF (Ctrl+P). Проверить вёрстку без бэкенда: `/r.html?demo=1`.

⚠ Два места, которые надо сверить на ПЕРВОМ тестовом платеже (помечены в коде): точное имя заголовка HMAC-подписи и имя поля с нашим lead_id в уведомлении TipTop (ExternalId/InvoiceId) — смотрим в логах функции и правим одну строку.

Готовый промпт для Claude API (текстовые блоки отчёта):

На входе JSON: профиль по 6 осям, портфель программ с двумя вероятностями (поступление/стипендия), бустеры, P(хотя бы один оффер). Напиши на русском, обращаясь на «ты», без воды: (1) вердикт одним предложением с числом условий; (2) «Точка Б» — кем человек будет в сентябре 2027, 2 предложения; (3) по 1 предложению контекста к каждой программе портфеля — почему она в списке и на что обратить внимание (используй поле note); (4) абзац «что усилить» по бустерам с точными +пп; (5) тёплый финальный абзац про следующий шаг с документами. Верни JSON с ключами verdict, point_b, programs[{id, comment}], boosters_text, next_step.

Ключ хранится только в твоём браузере. Показывает: посетители, воронка (заход → квиз →
пейволл → оплата), оплатившие со статусом отчёта, последние анкеты, заявки с формы.
Никому не давать ссылку вместе с ключом — ключ даёт полный доступ к базе.

- `events`: где воронка течёт (quiz_step по шагам → paywall_view → pay_click → pay_result). Первая чинимая дыра будет видна за 20–30 прохождений.

- Проверка базы программ: Диас А. идёт по `data/programs-expansion.json` (91 кандидат в файле и в таблице `programs` в Supabase; там же `data/universities-qs.json` — 100 университетов QS-2026, все с официальными ссылками), помогает `scripts/crawl-programs.mjs` (запускать локально).
